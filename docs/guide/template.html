Hướng dẫn dùng QA Flow Hub

QA Flow Hub gom quy trình test của bạn về một chỗ: lấy story từ Jira, AI phân tích requirement và viết test case, đẩy sang TestLink, chấm kết quả theo từng round và môi trường, log sub-bug, viết report, chạy test tự động. Tài liệu này đi từ cài đặt, dùng thử không cần tài khoản, tới lấy từng loại token để nối với hệ thống thật.

01Bắt đầu nhanh

  1. Mở toolGiải nén gói zip rồi bấm đúp file start, trình duyệt tự mở. Xem mục 2.
  2. Tạo tài khoản AdminLần đầu mở, tool hỏi tên, email và mật khẩu. Đây là tài khoản quản trị của bạn.
  3. Bấm “Tạo dự án mẫu”Có ngay 3 story, 14 test case, một round DEV đã chạy kèm bug để bạn thử mọi màn mà chưa cần token nào.
  4. Khi muốn dùng thậtLấy API key Gemini, token Jira, API key TestLink theo mục 5, nhập ở Quản trị → Kết nối.

Không cần token

Dùng thử dự án mẫu: chấm kết quả, log bug, verify, round 2, report, gate.

Cần Gemini

AI phân tích requirement, sinh test case, viết bug, viết nhận xét report, chạy test tự động.

Cần Jira + TestLink

Đồng bộ sprint thật, gửi Q&A, tạo sub-bug trên Jira, đẩy test case và kết quả sang TestLink.

03Lần đầu mở

Tool hỏi tạo tài khoản Admin đầu tiên. Admin quản lý kết nối, dự án và thành viên. Sau đó bạn vào màn Thiết lập với 5 bước; bước nào chưa làm có nút Làm dẫn thẳng tới chỗ cần nhập.

05Lấy token và kết nối

Mọi kết nối nhập ở Quản trị → Kết nối (chỉ Admin thấy). Bấm Lưu và kiểm tra: tool gọi thử và báo đúng sai ngay. Token được mã hoá, màn hình chỉ hiện 4 ký tự cuối.

Đừng gửi token qua chatTự dán token vào tool. Ai có token là làm được mọi việc mà tài khoản đó làm được.

Gemini (AI)

  1. Mở Google AI StudioVào aistudio.google.com/apikey, đăng nhập tài khoản Google.
  2. Tạo keyBấm Create API key, chọn hoặc tạo project, rồi copy key (bắt đầu bằng AIza…).
  3. Nhập vào toolKết nối → Gemini: Model ví dụ gemini-3.5-flash, dán API key, để trống Base URL, bấm Lưu và kiểm tra.
ModelBáo “Không tìm thấy model” thì mở AI Studio xem tên model đang có và sửa lại ô Model. Gói miễn phí có giới hạn số lần gọi mỗi phút: chạy tự động nhiều test case có thể chạm giới hạn, chờ một lúc rồi chạy tiếp.

Jira

  1. Mở trang tokenĐăng nhập Atlassian bằng tài khoản sẽ dùng cho tool, vào id.atlassian.com → Security → API tokens.
  2. Tạo tokenBấm Create API token (loại thường, không chọn loại “with scopes”), đặt tên ví dụ QA Flow Hub, chọn ngày hết hạn, rồi copy token. Token chỉ hiện một lần.
  3. Nhập vào toolKết nối → Jira: Base URL https://tencongty.atlassian.net, Loại Jira Cloud, Email đúng email của tài khoản vừa tạo token, dán token, bấm Lưu và kiểm tra.
  1. Tạo Personal Access TokenTrên Jira: ảnh đại diện → Profile → Personal Access Tokens → Create token, copy token.
  2. Nhập vào toolBase URL là địa chỉ Jira công ty, Loại Server / Data Center, để trống Email, dán token.
Nên dùng tài khoản riêng cho toolBug và comment tool tạo sẽ đứng tên tài khoản này. Tài khoản cần quyền trên dự án: xem issue, tạo issue, comment, đính kèm file, chuyển trạng thái.

TestLink

  1. Bật API (Admin TestLink làm một lần)Trong file custom_config.inc.php của TestLink có dòng $tlCfg->api->enabled = TRUE;.
  2. Lấy API keyĐăng nhập TestLink → My Settings → mục API interface → Generate a new key, copy key.
  3. Nhập vào toolKết nối → TestLink: URL https://testlink.congty.vn/lib/api/xmlrpc/v1/xmlrpc.php, Login tác giả là username TestLink của bạn, dán API key.
Chưa bật được API?Bỏ qua bước này. Ở tab Tổng quan của story bấm Tải XML TestLink, rồi trong TestLink vào Test Specification, chọn suite, Import file đó như hiện tại.

Slack (tuỳ chọn)

  1. Tạo appVào api.slack.com/apps → Create New App → From scratch, đặt tên, chọn workspace.
  2. Bật Incoming WebhooksTrong app: Incoming Webhooks → bật On → Add New Webhook → chọn kênh (ví dụ #qa-op) → Allow. Workspace có thể cần Admin Slack duyệt.
  3. Nhập vào toolKết nối → Slack: dán Webhook URL (https://hooks.slack.com/services/…), bấm Lưu và kiểm tra: kênh sẽ nhận một tin nhắn thử.

Tool gửi vào kênh: report đã đăng, báo dev deploy, bug dev chuyển Resolved cần verify.

Dự án, URL môi trường, tài khoản test

Quản trị → Dự án và ánh xạ → Thêm dự án:

  • Mã dự án Jira: ví dụ OP.
  • Jira board id: mở board trên Jira, số trong địa chỉ là board id. Ví dụ …/projects/OP/boards/42 hoặc RapidBoard.jspa?rapidView=42.
  • Tên project trên TestLink: gõ đúng tên như trong TestLink.
  • Issue type Story / Sub-bug: đúng tên trong Jira (Project settings → Issue types).
  • Field Severity / Environment: nếu Jira có. Mã field dạng customfield_10045, xem trong đường dẫn khi mở field ở trang quản lý Custom fields.
  • Trạng thái Resolved / Closed / mở lại: tên trạng thái trên workflow bug của team, cách nhau bằng dấu phẩy.
  • URL môi trường DEV / STAGING / PRODUCTION và tài khoản test: dùng cho chạy tự động. Mật khẩu được mã hoá, không hiện lại, không gửi cho AI.

Xong thì về Sprint board, chọn dự án ở góc trên, bấm Đồng bộ Jira.

07Chạy test tự động và kết quả API

Ở tab Thực thi, khung Chạy tự động: AI đọc từng test case, tool tự mở Chrome (Windows dùng Edge cũng được) thao tác trên URL môi trường, ghi Passed / Failed / Blocked kèm ảnh chụp. Test case loại API được gọi thẳng, không mở trình duyệt.

  1. Chuẩn bịĐã kết nối Gemini; dự án có URL môi trường và tài khoản test (dự án mẫu đã có sẵn).
  2. Bấm Chạy tự độngMặc định chạy các test case chưa chạy. Tick Chạy lại cả TC Failed / Blocked để chạy lại, tick Hiện cửa sổ trình duyệt để xem AI thao tác.
  3. Theo dõiThanh tiến độ và nhật ký tự cập nhật. Có thể bấm Huỷ lượt chạy.
  4. Duyệt kết quảKết quả có nhãn “Tự động · chờ duyệt”. Xem ghi chú, ảnh, kết quả API rồi bấm Duyệt tất cả hoặc sửa lại. Test case Failed thì bấm AI viết bug.

Kết quả API: mỗi test case có mục API (n lời gọi · m lỗi) liệt kê method, đường dẫn, mã trạng thái, thời gian, request và response. Test giao diện cũng ghi lại các API mà trang đã gọi trong lúc chạy. Lời gọi 4xx/5xx được tô màu. Tab Báo cáo có phần Kết quả API tổng hợp các lời gọi lỗi.

Để AI chạy chuẩnViết bước cụ thể (bấm nút nào, gõ gì, thấy gì). Test case cần thao tác đặc biệt như ngắt mạng sẽ được đánh Blocked kèm ghi chú “cần test tay”. Test case loại API ghi rõ method và đường dẫn, ví dụ DELETE /api/mapdecks/123 → HTTP 404.

08Dashboard, Việc của tôi, Regression và AI

Dashboard

Trang mở đầu sau khi đăng nhập. Gồm pass rate hiện tại, số test case chưa chạy, bug đang mở và chờ verify, thời gian fix trung bình, tỉ lệ chạy tự động; biểu đồ kết quả 14 ngày, tiến độ sprint, bug theo mức độ, story theo giai đoạn; bảng story cần chú ý và khối lượng việc từng người. Rê chuột lên cột để xem số; bấm Xem bảng số liệu để xem dạng bảng.

  • Xuất Excel: ba nút Story, Kết quả test, Bug tải file CSV mở được bằng Excel (giữ đúng tiếng Việt).
  • Hỏi AI về dự án: gõ câu hỏi như “Story nào rủi ro nhất và vì sao?”, “Tóm tắt tình hình cho standup”. AI chỉ trả lời dựa trên số liệu của dự án; câu trả lời được lưu lại bên dưới.

Việc của tôi và thông báo

Mở một story, bấm Nhận story để thành người phụ trách. Trang Việc của tôi gom mọi việc cần làm trên các story của bạn: test case chưa chạy, bug chờ verify, nháp AI chờ duyệt, câu trả lời Q&A, report chưa đăng, story đã đạt gate. Chưa nhận story nào thì trang hiện việc của cả dự án.

Chuông ở góc trên báo khi: dev chuyển bug sang Resolved, BA/PO trả lời Q&A trên Jira, Antigravity tạo nháp, story chuyển môi trường, lượt chạy tự động hoặc regression xong. Bấm vào thông báo để mở đúng chỗ.

Regression và lịch chạy tự động

  1. Tạo bộMenu Regression → Tạo bộ regression: đặt tên (ví dụ “Smoke STAGING”), chọn môi trường.
  2. Chọn test caseTick test case từ nhiều story; có nút chọn nhanh mọi happy case hoặc mọi test case API.
  3. Lên lịchChọn Hằng ngày hoặc Thứ 2 – thứ 6 và giờ chạy (giờ Việt Nam). Lịch chỉ chạy khi tool đang mở.
  4. Chạy và xem kết quảChạy ngay hoặc chờ đến giờ. Xong sẽ có thông báo, tin Slack (nếu đã kết nối) và bảng kết quả từng test case kèm số lỗi API.

AI kiểm tra độ phủ và cảnh báo bug trùng

  • Độ phủ yêu cầu (tab Tổng quan của story): bảng AC ↔ test case tự tính theo cột Ref. Bấm AI kiểm tra độ phủ để AI đối chiếu requirement, Q&A với test case, đánh dấu chỗ thiếu và gợi ý test case; bấm Thêm thành nháp để đưa gợi ý vào hàng chờ duyệt.
  • Bug có thể trùng: khi soạn nháp bug, tool so với các bug đã có trong dự án và cảnh báo nếu giống nhau, kèm link để kiểm tra trước khi tạo.

09Kết nối Antigravity (tuỳ chọn)

Nếu bạn dùng Antigravity, agent trong đó có thể đọc test case, tự chạy trên trình duyệt và gửi kết quả, ảnh, lời gọi API, nháp bug về tool qua MCP.

  1. Tạo token MCPGóc trên bên phải → Hồ sơ và token MCP → đặt tên (ví dụ Antigravity · MacBook), quyền Đọc + ghi → Tạo token. Token chỉ hiện một lần.
  2. Copy cấu hìnhBấm Copy cấu hình. Đoạn này đã có sẵn đường dẫn tới chương trình kết nối nằm trong thư mục tool và token của bạn.
  3. Dán vào AntigravityMở phần quản lý MCP server của Antigravity (thường ở menu “…” của khung Agent → MCP Servers → Manage MCP Servers → View raw config; tên menu có thể khác tuỳ phiên bản), dán vào mục mcpServers, lưu và làm mới.
  4. Ra lệnh cho agentỞ tab Thực thi của story, khung Chạy bằng Antigravity có câu lệnh soạn sẵn cho build đang mở: bấm Copy câu lệnh cho Antigravity rồi dán vào khung chat của agent.
Lưu ýTool phải đang chạy khi agent làm việc. Mọi thứ agent ghi đều chờ bạn duyệt ở menu AI Agent. Không dùng máy nữa thì Thu hồi token ở Hồ sơ.

10Lỗi thường gặp

Quên mật khẩuNhờ Admin Đặt lại mật khẩu ở màn Người dùng và quyền.

11Bảo mật và sao lưu

  • Toàn bộ dữ liệu (tài khoản, story, test case, ảnh, token đã nhập) nằm trong thư mục data cạnh file start (chạy từ source thì là .data).
  • Sao lưu: tắt tool, copy thư mục data đi chỗ khác. Lên bản mới: giải nén bản mới, copy thư mục data cũ sang, rồi mở.
  • Không gửi thư mục data cho người khác: trong đó có khoá giải mã các token.
  • Mặc định chỉ máy bạn mở được tool. Muốn đồng nghiệp cùng mạng LAN dùng chung, xem file HUONG-DAN.txt trong gói.
  • Đổi mật khẩu sẽ đăng xuất mọi phiên đăng nhập khác. Nghi lộ token Jira/Gemini thì thu hồi ở trang gốc rồi nhập token mới ở màn Kết nối.
